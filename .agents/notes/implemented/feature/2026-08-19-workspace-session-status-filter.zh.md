# Agent Note：工作区会话状态筛选

Status: implemented

[English](2026-08-19-workspace-session-status-filter.md) | 中文

## 问题

侧边栏的工作区浏览器会把一个工作区组内的每个可见会话都列出来，繁忙的目录下正在工作的行与早已结束的行混在一起。唯一的收敛途径是文本搜索，它匹配的是标题和内容，而不是会话此刻正在做什么。

## 决策

视图菜单新增第三段 **状态**，含三个选项：**全部**、**运行中**、**已完成**。活动定义为三个来源的并集：会话自身的 `running` 位、等待中的 `pendingInteraction`（审批、计划审阅或提问），以及经不间断 subagent-origin 谱系可达的任何运行中后代（`runningSubagentCount`）。**运行中**只保留活跃行；**已完成**是非空白行上的补集——已结束的会话无论绿色未读完成提醒是否仍处于触发状态都保持列出——临时的空白「新会话」行只出现在**全部**下。筛选对分组和单列表两种呈现方式生效，并持久化在浏览器视图 store 中（`statusFilter`，默认 `'all'`）；搜索结果不受影响，因为文本查询本就替换掉任一浏览模式。

推导在行级别筛选（`sessionStatusMatches`，在 `deriveGroups` 与 `deriveFlat` 内部应用），因此组成员身份和各记账的顺序记录从不改变：被筛掉的行保留自己的顺序席位，切回**全部**即可还原此前的精确排列。分组头始终可见并携带筛选后的计数；某个工作区的会话被全部筛掉时，其分组头仍然渲染。浏览器本地的 Ungrouped 桶在筛选隐藏了全部松散会话时会消失——与归档规则一致——从而筛选空态文案得以出现；出现时，它会替代任一呈现方式下的无会话空态。单列表为顺序记账派生未筛选的行，再从完整顺序投影可见行，因此筛选状态下的拖拽是对完整记账提交位置，而不是修剪被隐藏的 id。

该存储字段声明为可选，因为旧版本构建持久化的状态早于该字段（localStorage 水合会整体替换值）；读取端默认 `'all'`。

## 备选方案

**运行中仅指会话自身的 `running` 位。** 等待审批或等待回答的会话会从两个筛选视图中同时消失，而带有活跃子代理的父会话会被读成已结束。

**以绿色未读完成提醒作为已完成。** 打开会话会清除该提醒，于是按已完成筛选的用户会在阅读过程中看着行逐个消失；该标签应当描述已结束的工作，而非未读状态。

**隐藏行全部被筛掉的工作区分组。** 浏览器把工作区头视为持久的导航条目，即便为空也如此；隐藏它们会让侧边栏布局随会话启停而跳动。

**在区头下方增设一排专用分段控件。** 视图菜单已经聚合了所有呈现偏好，筛选加入其中即可，无需新增常驻界面元素；独立的一行会占用紧凑侧边栏刻意节省的纵向空间。

**把筛选也应用于搜索结果。** 搜索本就替换浏览模式并匹配内容；把两个正交的收敛叠加在一起需要一套专属的结果页界面，还会模糊掉究竟是哪个条件移除了某一行。

## 后果

- 工作区浏览器中的会话行可被收敛为恰好是活跃集合或已结束集合，两种呈现方式都可用；选择在重载后保持。
- 筛选从不改写持久化的工作区记账或浏览器本地的各记账顺序：可见性只是同一批行与顺序上的纯投影。
- 单列表的顺序记账现在从未筛选的行列表派生，这同时也是筛选前的一贯行为；筛选状态下的拖拽对完整顺序提交。
- 分组头在任何筛选下都保持渲染，`sessionCount` 反映筛选后的可见行。
- 不含 `statusFilter` 的旧持久化视图状态在用户选择筛选前都表现为**全部**。

## 测试

树推导测试覆盖 `sessionStatusMatches` 对自身运行、等待交互、后代活动、空白行与已完成补集的判定，以及带筛选的 `deriveGroups`（计数、成员与消失的 ungrouped 桶）和 `deriveFlat`（按时间排序、当前空白行在全部之外被排除）。浏览器测试覆盖菜单新分段的展示与选中勾记、分组与单列表两种模式下的筛选、重挂载后的筛选持久化、不含该字段的旧持久化状态，以及筛选隐藏全部行时两种呈现方式下的筛选空态文案。既有 store 测试断言 `statusFilter` 的默认值与 action。
