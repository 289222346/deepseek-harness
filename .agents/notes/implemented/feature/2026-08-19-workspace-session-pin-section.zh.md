# Agent Note：工作区会话置顶区

Status: implemented

[English](2026-08-19-workspace-session-pin-section.md) | 中文

## 问题

繁忙的工作区把用户正在关注的会话和其他一切混在一起，且没有任何排序偏好能把某一个会话固定留在视野中：手动排序和活动置顶出于其他原因移动行，状态筛选能减少行数，却不会为特定会话保留位置。

## 决策

会话行菜单新增**关注**／**取消关注**（`dsh-client-ui-primitives` 新增一枚 `IconPinOutline16` 产品图形）。被关注的会话移入渲染在所有工作区分组上方——单列表模式下则在列表上方——的**置顶**区，按关注时间从新到旧排列；该区没有可见行时消失。置顶区是浏览器本地的纯投影：关注从不改写 Host 工作区记账、浏览器本地各记账顺序或单列表顺序记账，因此取消关注会让行回到原来的位置。关注折叠分组中的会话与归档、重命名一样由行菜单完成手势；置顶行保留重命名、分叉与归档操作，但在置顶区内不可拖拽。

置顶集合存放在工作区视图 store 中（`pinnedSessionIds`，按关注顺序、最新在前；旧版本构建持久化的状态没有该字段，读取端默认空集）。`derivePinnedSessions` 投影置顶区——按关注顺序取本应可见的行：已归档、subagent-origin、空白与被状态筛选排除的 id 从不出现，因此状态筛选在置顶区内同样生效。`deriveGroups` 与 `deriveFlat` 从各自行中排除置顶 id，同时每个记账保留自己的席位；当筛选或置顶集合隐藏了全部松散会话时，Ungrouped 桶消失（沿用既有归档规则）。无会话与筛选空态文案在置顶区有行时让位于置顶区。

## 备选方案

**置顶到每个工作区分组内部而不是全局置顶区。** 被置顶的会话在很长的分组里仍会滚出视野，单列表呈现又需要第二条规则；一个位于所有内容上方的区是两种呈现共用的单一机制。

**关注时改写 Host 工作区记账。** 浏览器呈现偏好会覆盖共享的持久化记账，这正是手动排序决策已否定的失败模式（[工作区侧边栏顺序与折叠](2026-08-11-workspace-sidebar-order-and-folding.md)）。

**置顶状态 Host 持久化（像 `session/title` 一样写会话日志事件）。** 跨端同步需要新事件类型、投影、Host RPC、`SessionSummary` 字段与双 SDK 界面；仅用于呈现的消费方撑不起这样的表面积，而浏览器本地 store 已能跨重载保持。

**拖入置顶区。** 拖入需要发明「拖拽即关注」手势，拖出需要「拖拽即取消关注」；行菜单开关用现成机制覆盖了两个方向。

**在原行上加置顶标识。** 置顶区本身已表明关注状态；第二个指示器会在两处重复陈述同一事实。

## 后果

- 被关注的会话始终位于侧边栏顶部（分组或单列表），按关注顺序排列，直到取消关注；取消关注恢复此前的精确记账位置。
- 状态筛选与归档规则在置顶区内与其他位置完全一致地生效；关注是排序而非可见性。
- 单列表顺序记账从未置顶的行列表派生，因此关注永远不会把隐藏 id 从持久化顺序中剪掉。
- 该 store 字段对旧持久化状态保持可选；读取端默认空集。
- `dsh-client-ui-primitives` 多导出一枚产品图形（图标总数 71）。

## 测试

树推导测试覆盖 `derivePinnedSessions` 的关注顺序、`pinned` 标记，以及对未知、已归档、subagent-origin、空白与被筛选 id 的排除；置顶行从分组与单列表的投影移出且记账原样保留；Ungrouped 桶消失；全部置顶时空工作区头仍渲染。浏览器测试覆盖行菜单关注/取消关注与工作区上方的置顶区、取消关注后的位置恢复、重挂载持久化、单列表置顶区与记账保留，以及置顶区内的状态筛选。行测试覆盖两种状态下的关注菜单文案与派发。store 测试覆盖关注顺序的前插与移除 action；图标测试套件钉住新图形的数量与调色板约束。
